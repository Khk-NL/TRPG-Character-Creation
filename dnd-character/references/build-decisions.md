# 选择与配合

用于玩家委托 Agent 补全的选择。目标是让角色在当前等级、允许规则与实际场景中好用，并保留其人设。若玩家已经选定某项，先以该选择为约束；发现合法性冲突则指出具体原因，不静默替换。

## 先建立决策依据

从玩家输入和公告提取：角色主要定位、希望有的辅助贡献、战斗/探索/社交比重、当前等级、明确的成长计划、原始属性是否已指定对应、允许来源、房规与预算。属性未分配时可按定位分配；已有明确对应时保留。

队伍配置只使用已知信息。未知时写“未知”，选择独立可用的方案；不假设队友一定会开锁、治疗、侦察、提供照明或让敌人倒地。不要为覆盖全部职责而把每个选择都分散；稳定完成主定位，再补一种实际需要的场外贡献。

## 熟练项分配顺序

1. 列出每个来源：职业、背景、物种/种族、专长、子职等；注明固定项目、自选数量、候选范围和取得等级。技能、工具、语言、豁免、武器熟练与武器精通分别处理。
2. 先扣除固定项目，再安排候选范围最窄的选择，最后用自由选择补缺口。若已知背景给运动，不在职业的有限自选中再次选运动。只有对应版本规则或房规允许时，才替换重复熟练；重复本身不自动变成专精。
3. 在合法候选之间比较：模组实际用途、角色经常执行的行为、当前属性/熟练后的加值、队伍已知覆盖、人设关联、其他选项能否更便宜地完成同一目标。不按清单从前往后选，也不固定所有角色都拿同一套技能。
4. 高属性与高频用途匹配时优先强化；低属性技能若是玩家想承担的核心职责，也可以投入，但说明当前收益和代价。背景固定授予的低属性熟练仍然保留，不把它描述成角色的强项。
5. 专精只给规则允许且已熟练的项目。比较“把核心职责做稳”与“增加另一项覆盖”的收益；不能因为有两份熟练来源就把熟练加值加两次。

技能说明应能落到动作：例如探索中的观察、查找线索、判断动机，或实际承担的交涉。不要把同为敏捷的特技、隐匿等技能当作可以互换，也不承诺某技能能替代所有相关工具操作。若想用不同属性做技能检定，须有规则/DM支持，不把可选判定当成常驻收益。

工具要有合法来源和可用场景，必要时核对是否实际携带或能借用。2024规则下，同一次检定确实同时适用工具熟练和技能熟练时可获得优势；不能把它写成对该技能的永久优势或两次熟练加值。2014卡不自动套用2024工具规则；可选扩展须获准。语言结合公开地区、人设和交流对象选择，不凭职业默认“必学”。

## 把选择放进完整方案

选择背景、专长、武器/精通、战斗风格、法术或物品时，核对它们是否支持同一个可执行的打法，以及是否有不同场景的替代手段：

- **攻击与属性：**用实际攻击属性、伤害、DC和适用攻击类型判断收益。技能熟练不提高攻击命中；武器熟练也不等于已解锁该武器精通。不要只凭“职业通常靠某属性”判断这张卡。
- **动作与持用：**动作、附赠动作、反应能否在同一回合安排；是否需空手、双手、盾牌或法器；触发时机与范围是否允许组合。不能把两个附赠动作列作同回合连招。
- **专注与条件：**需专注的效果能否同时维持；控制是否要求目标豁免失败、体型适合或其他条件。区分“必然能提供的效果”和“满足条件后的收益”。
- **资源与遭遇：**常态轮次靠什么行动、何时爆发、资源耗尽后还能做什么。多遭遇模组重视持续性；不能把每回合消耗稀缺资源当成常态伤害。戏法不是所有职业的必需选项，武器攻击通常不消耗法术位。
- **防御与队伍：**护甲/盾是否与隐匿任务、持用要求和预算相容；控制/增益是否方便已知队友利用。明确的成长目标可作同等选项间的取舍依据，但未来能力不得计入当前效果。

有真实取舍时比较最相关的备选，再给一套推荐；不为每个字段堆叠多个方案。关键理由写成“选择 → 作用 → 与什么配合 → 放弃什么”，普通无争议项目不逐项长篇解释。已有明确偏好通常不必重新询问；只有会显著改变人物方向且缺乏依据时才确认。

## 选择示例（不是默认配置）

- **固定力量高、魅力低的近战角色：**先保留属性与背景固定项；可从合法来源安排运动和一种探索技能，额外自选避免与背景重复。低魅力时评估不依赖自身法术命中/DC的进攻手段，但玩家明确要交涉时不能擅自取消其定位。职业技能不足以提供想要的项目时，检查真正拥有的自由熟练来源，不凭空授予。
- **明确承担交涉的角色：**核心交涉技能与洞悉可互补；专精优先考虑其实际职责，而非只挑面板最高者。若队伍已有交涉者，是否保留重叠取决于玩家定位和群体场景，不能一律删除。
- **侦察/工具角色：**隐匿、察觉、调查与相应工具承担不同环节，不要求每人全选；按来源数量和任务取舍。检查护甲的隐匿劣势、工具是否携带，以及已知队友能否跟上打法。

这些例子只展示决策方法，不能代替职业/背景的合法候选和数量核对。

## 计划与交付

Agent 代选时填写 `build_strategy`（结构见[计划字段](plan-schema.md#建卡决策记录)），记录主要定位、队伍信息、技能/专精/工具来源和少量关键选择。脚本检查来源记录与最终熟练清单一致，并把理由写入战斗速查；它不自动证明来源合法，也不评判打法强弱。仍须按对应版本核对原文。

验收时检查：没有重复浪费受限选择；没有无来源的熟练/专精；主要任务有实际手段；相互配合的选择不存在动作、专注、属性、资源或装备冲突；已知短板与取舍已说明。没有适用配合时不要编造“联动”。
